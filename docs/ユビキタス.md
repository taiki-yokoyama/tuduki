# ユビキタス言語

## 目的

このプロジェクトで使う業務用語とコード上の名前を統一する。

新しい画面、API、DB、モデル、テストを追加するときは、この文書の正規語を使う。
既存コードに別名が残っている場合は、互換維持のための移行対象として扱い、新規実装では再利用しない。

## 最上位の正規語

| 日本語 | 正規語 | 意味 | 使わない名前 |
| --- | --- | --- | --- |
| ユーザー | user / users | 認証され、データを所有するアカウント | account, owner, member, User |
| 日記 | Diary / diary | ユーザーが1件書く記録 | note, memo, log, post, record |

user と diary はこのプロダクトの中心語とする。画面、API、DB、Laravel モデル、React 型、テストで同じ意味のものに別名を付けない。
PHP のクラス名など言語規約上 PascalCase が必要な場合だけ User を使い、ドメイン用語・API・DB の表記は user / users に固定する。

## ドメイン用語

| 日本語 | 正規語 | 定義 | 命名例 |
| --- | --- | --- | --- |
| 人物 | Person | 日記に登場する、一緒にいた人 | Person, /people, person_id |
| グループ | Group / groups | 人物を整理する分類 | Group, /groups, group_id |
| 日記と人物の関連 | DiaryPerson / diary_people | 日記に人物を紐づける多対多の関連 | diary_id, person_id |
| 日記画像 | DiaryImage / diary_images | 日記に添付された画像のメタデータ | DiaryImage, diary_id |
| 画像ファイル | ImageAsset / image asset | Storage に保存される実体 | storage_path, url |
| 本文 | content | 日記の本文 | content |
| 日記の日付 | diary_date | その日記が対象とする暦日 | diary_date |

### Person と people の使い分け

ドメイン用語は常に Person とする。
people は、URL、DB テーブル、一覧レスポンスなど「Person の集合」を表す技術上の複数形にだけ使う。

- クラス、モデル、型、Schema: Person
- ID、外部キー: person / person_id
- URL、DB テーブル、配列: people
- People をクラス名やドメインモデル名には使わない
- persons と誤記された複数形は使わない

### 日記と画像の区別

DiaryImage は DB 上の関連データ、ImageAsset は Storage 上のファイル実体を指す。
画像をアップロードする処理と、日記に画像を紐づける処理は別の責務として扱う。

## 認証・所有権

| 概念 | 正規語 | ルール |
| --- | --- | --- |
| 認証 | authentication | user が本人であることの確認 |
| 認可 | authorization | user が対象データを操作できるかの確認 |
| 所有者 | user_id | Diary、Person、Group、DiaryImage の所有 user |
| セッション Cookie | session cookie | Sanctum が認証状態を保持する Cookie |
| CSRF トークン | X-XSRF-TOKEN | 状態変更リクエストに付ける CSRF ヘッダー |

owner は説明文では使ってよいが、ドメインモデル名・DB カラム名・API フィールド名には使わない。
所有者を表す ID は必ず user_id とする。

## 日付・時刻

| 用途 | 正規語 | 型 |
| --- | --- | --- |
| 日記の日付 | diary_date | date / YYYY-MM-DD |
| 作成日時 | created_at | timestamp |
| 更新日時 | updated_at | timestamp |

written_at、date を日記の日付の意味では使わない。
日付範囲検索のパラメータは start_date / end_date とし、対象フィールドは diary_date とする。

## API 命名規則

### リソース

- ユーザーリソース: /users（user の集合）
- グループ: /groups
- 人物リソース: /people（Person の集合を表す技術上の URL）
- 日記: /diaries
- 日記と人物の関連: /diaries/{diary}/people
- 日記画像: /diaries/{diary}/images
- 画像アップロード: /images

### パラメータ・レスポンス

- 日記 ID: diary
- 日記の外部キー: diary_id
- 人物 ID: person
- 人物の外部キー: person_id
- 日記一覧: diaries
- 日記 1 件: diary
- operationId は listDiaries, createDiary, getDiary, updateDiary, deleteDiary の形式にする

## 現在確認できている揺れと対応

| 現状の名前 | 正規語 | 対応 |
| --- | --- | --- |
| body | content | API・DB・React 型で content に統一する |
| written_at | diary_date | API・DB・React 型で diary_date に統一する |
| title, mood | なし | 現行 scaffold の暫定項目。Diary 移行時に削除する |
| Memora | Tuduki | Tuduki をリポジトリ・プロジェクト名とする。Memora は旧 UI 表示名として扱う |

## 追加で揺れやすい論点

| 論点 | 現状 | 先に決める方針 |
| --- | --- | --- |
| 認証基盤 | main は Supabase Auth、develop は Laravel API | Laravel Sanctum の SPA Cookie/Session 方式に固定する |
| 削除方式 | 元スキーマは関連を cascade / set null | Diary と DiaryImage は cascade、Group 削除時の Person は group_id を null、user 削除時は所有データを cascade |
| 画像の寿命 | Storage と DB メタデータを別々に操作 | ImageAsset の削除と DiaryImage の削除を同一ユースケースで扱い、孤立ファイルを残さない |
| 公開範囲 | main は認証ユーザー自身のデータだけ | 全リソースに user_id を持たせ、user 単位で認可する |
| API のエラー形式 | Laravel 標準と Supabase の形式が異なる | 全 API で message と errors を持つ Laravel 形式に統一する |

日記の属性は content と diary_date を基本とする。title と mood は日記のドメインモデルに持たせない。

## 意図的に使い分ける語

### user と authentication

user はドメイン上のアカウント、authentication は本人確認の仕組み。
「認証ユーザー」のように混ぜず、データの所有者は常に user と表現する。

### DiaryImage と ImageAsset

DiaryImage は日記との関連、ImageAsset はファイルそのもの。
Storage のパスは storage_path、公開 URL は url とする。

### Group と tag

人物を分類するものは Group とする。
日記に人物を紐づける操作は「タグ付け」と呼んでもよいが、モデル・テーブル・API の名前は DiaryPerson を使う。

## 新しい用語を追加する場合

1. 既存の正規語で表現できないか確認する。
2. 日本語の意味、英語の正規語、対象範囲、禁止する別名をこの文書に追加する。
3. DB、API、Laravel、React の命名を同じ正規語に揃える。
4. 既存コードとの互換が必要な場合は、移行期限または変換箇所を記録する。
